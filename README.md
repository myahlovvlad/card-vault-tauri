# CardVault

Кроссплатформенная электронная визитница на **Tauri 2 + React + TypeScript + Vite**. Один frontend запускается как обычное web-приложение и упаковывается в native-приложения для Windows, macOS, Linux, Android и iOS.

## Готовые сборки

Установщики для Windows и Android — на странице [Releases](https://github.com/myahlovvlad/card-vault-tauri/releases). Перенос данных между устройствами — через **Экспорт → Резервная копия JSON** / **Экспорт → Импорт JSON** (см. «Хранение и перенос данных» ниже); полноценная облачная синхронизация не реализована.

### Подпись Android release-сборки

`tauri android build` (без `--debug`) подписывает APK ключом из `src-tauri/gen/android/keystore.properties` (формат: `storeFile`/`storePassword`/`keyAlias`/`keyPassword`). Этот файл и сам keystore **не входят в репозиторий** (внутри `src-tauri/gen/`, которая целиком в `.gitignore`) — они должны существовать локально на машине, выполняющей release-сборку. Если файла нет, `signingConfigs["release"]` в `app/build.gradle.kts` просто не создаётся и релизная сборка получится неподписанной. Чтобы сгенерировать новый keystore:

```bash
keytool -genkeypair -v -keystore <путь>/cardvault-release.jks -alias cardvault -keyalg RSA -keysize 2048 -validity 10000
```

и создать `src-tauri/gen/android/keystore.properties` с путём к нему и паролями. Храните keystore и пароль отдельно от репозитория — потеря ключа означает невозможность выпустить обновление, подписанное тем же сертификатом.

## Что уже реализовано

- загрузка нескольких фото одной визитки, с метками «лицевая / оборотная / другое»;
- автоматический OCR после загрузки фото и повторный ручной запуск OCR;
- распознавание русского + английского текста через Tesseract.js;
- подтверждение результата пользователем: OCR только предлагает значения, окончательные поля сохраняются после проверки формы;
- поля: имя, компания, должность, телефон, email, сайт, комментарий;
- папки/темы: создание, удаление и перенос визитки через редактирование;
- общая звезда «важно»; важные визитки автоматически сортируются первыми;
- полупрозрачная бордовая подсветка всей важной карточки;
- поиск по основным полям, комментариям и исходному OCR-тексту;
- локальное хранение данных и фотографий в IndexedDB;
- резервная копия / перенос на другой компьютер через JSON (фотографии входят в JSON как data URL);
- экспорт контактов в CSV;
- экспорт одной визитки в `.vcf` (vCard);
- адаптивный интерфейс для desktop и mobile;
- точка расширения для CRM-коннекторов (`src/lib/connectors.ts`);
- **«Мои визитки»**: создание одной или нескольких собственных визиток (без фото/OCR — только поля), отображаемых в виде «кошелька» карточек;
- **обмен по QR**: полноэкранный режим показа своей визитки — переворачиваемая карточка с большим QR-кодом (vCard) на одной стороне и данными на другой, плюс кнопка «Поделиться» (Web Share API) и экспорт `.vcf`;
- **сканер QR**: приём чужой визитки через камеру устройства (или ручной ввод текста как запасной вариант) с последующим подтверждением полей перед сохранением — так же, как после OCR.

## Быстрый запуск web-версии

Требования: Node.js 18+ (рекомендуется Node.js 22).

```bash
npm install
npm run dev
```

Откройте `http://localhost:1420`.

Production web build:

```bash
npm run build
npm run preview
```

Откройте `http://localhost:4173`.

## Запуск Tauri на desktop

Установите Rust и системные зависимости Tauri для своей ОС, затем:

```bash
npm install
npm run tauri:dev
```

Сборка установщика:

```bash
npm run tauri:build
```

## Android

После установки Android Studio / Android SDK / NDK и настройки Tauri mobile:

```bash
npm run android:init
npm run android:dev
```

Сборка:

```bash
npm run android:build
```

## iOS

Сборка iOS требует macOS + Xcode. На этой (Windows) машине нативная сборка/тест iOS невозможны — вместо этого настроен CI: `.github/workflows/ios.yml` собирает приложение под iOS Simulator на `macos-14` runner'е GitHub Actions при каждом push/PR (без сертификатов подписи, только для проверки, что Rust/Swift/webview-сторона собирается). Артефакт `cardvault-ios-simulator` доступен на вкладке Actions после сборки.

На Mac, для локальной разработки/тестирования на симуляторе или устройстве:

```bash
npm run ios:init
npm run ios:dev
```

Сборка:

```bash
npm run ios:build
```

## Мои визитки и обмен по QR

Раздел «Мои визитки» (в сайдбаре) — это ваши собственные визитки, отдельно от каталога полученных. Каждая карточка кодируется в vCard и превращается в QR: другой человек сканирует его камерой телефона и сразу получает ваши контакты — без сети и без сервера, весь QR — самодостаточный vCard-текст.

- **Показать QR** — открывает полноэкранный режим (переворачиваемая карточка): по умолчанию показан QR, тап переворачивает на данные визитки и обратно.
- **Поделиться** — системный share-sheet (Web Share API) с `.vcf`-файлом; если недоступен, предлагается скачать `.vcf` или скопировать vCard-текст.
- **Сканировать** (кнопка в шапке) — открывает камеру, распознаёт QR через `jsQR` и передаёт данные в тот же экран подтверждения, что и после OCR; при отсутствии доступа к камере (например, на desktop без веб-камеры) доступен ручной ввод текста.

Требует разрешения на камеру в браузере/WebView; на Android/iOS разрешение необходимо объявить в нативном проекте (`android:init`/`ios:init` создают его автоматически на основе `capabilities`, при необходимости добавьте `<uses-permission android:name="android.permission.CAMERA"/>` в сгенерированный `AndroidManifest.xml` и `NSCameraUsageDescription` в `Info.plist`, если сканер не запускается).

## Хранение и перенос данных

Данные не отправляются на сервер приложения. Они сохраняются локально в IndexedDB текущего web-профиля / Tauri WebView.

Для передачи базы коллеге используйте **Экспорт → Резервная копия JSON**. В архив входят и изображения. На другом устройстве используйте **Экспорт → Импорт JSON**.

Для ~50 визиток это практичнее, чем встраивание всей базы в исполняемый HTML-файл. Фотографии перед сохранением уменьшаются до максимальной стороны 1800 px и JPEG quality 0.84.

## OCR

OCR реализован через Tesseract.js 7. По умолчанию используется `rus+eng`. Tesseract.js загружает необходимые OCR-ресурсы при первом использовании; поэтому для первой OCR-сессии обычно требуется доступ к интернету. CRUD, папки, поиск и уже сохранённые данные работают локально.

Для полностью офлайн-сборки следующий шаг — положить worker/core/traineddata в assets проекта и передать локальные `workerPath`, `corePath`, `langPath` при создании OCR worker.

## CRM и календарь

В MVP заложен интерфейс `ContactConnector`, но OAuth/API конкретных CRM не включены. Следующий слой можно реализовать адаптерами для Bitrix24, amoCRM, HubSpot, Microsoft/Google Contacts/Calendar или собственного backend.

Рекомендуемая модель синхронизации:

1. локальная база остаётся source of truth;
2. коннектор маппит `BusinessCard` в объект CRM;
3. сохраняется внешний `remoteId` + время последней синхронизации;
4. конфликт разрешается пользователем;
5. массовые коммуникации выполняются только средствами CRM с учётом согласий и политик конкретной организации.

## Ограничения MVP

- эвристическое распределение OCR по полям не гарантирует корректность — именно поэтому пользователь подтверждает результат;
- нет облачного multi-user sync и разрешений «владелец/коллега»;
- нет готового OAuth к CRM/календарю;
- iOS собирается только на macOS/Xcode; локально (Windows) недоступна ни сборка, ни установка на симулятор/устройство — только CI-сборка под Simulator (см. выше);
- Android/iOS требуют стандартной инициализации Tauri mobile target на машине разработчика;
- HEIC зависит от декодера WebView; при проблемах лучше использовать JPG/PNG;
- сканер QR использует `getUserMedia`, а не нативный Tauri-плагин камеры — без разрешения на камеру в системе доступен только ручной ввод текста.

## Roadmap к production

- bundled offline OCR models;
- SQLite через Tauri SQL plugin для native targets + миграции;
- шифрование локальной базы и PIN/biometric lock;
- роли Owner / Reviewer (reviewer меняет только комментарий и звезду);
- двусторонняя CRM sync + conflict resolution;
- Google/Microsoft calendar/contact connectors;
- нативный camera capture flow на Android/iOS (сейчас — `getUserMedia` + `jsQR`, без нативного плагина);
- duplicate detection по email/phone/company;
- audit log изменений;
- unit/e2e тесты и release pipelines для installers/mobile stores.
